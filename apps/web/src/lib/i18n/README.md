# i18n: message catalogue

Thai (`th`, default) and English (`en`). No i18n framework; about 100 lines of code.

## Use it

```tsx
"use client";
import { useT } from "@/lib/i18n";

export function Example() {
  const t = useT();
  return <h1>{t.nav.learn.title}</h1>;
}
```

`useLanguage()` returns `{ lang, t, setLang }` when you also need the language itself (for
number formatting, or the switch).

## Add messages

1. Add the message to `messages/th.ts`. It is the master: the type of the catalogue comes from it.
2. Add the same key to `messages/en.ts`. A missing or extra key is a **type error**
   (`npm run typecheck`), so a language can never silently show a blank.
3. A message with a value in it is a function: `learnStep: (n: number) => `คาบที่ ${n}``.

Group messages by page or component (`nav`, `shell`, `learn.period2`, ...). Other sessions add
their own group; do not reshuffle someone else's.

## Rules

- A term you are unsure of in Thai: write your best draft and add it to
  `docs/classroom/kit/glossary.md` with a `ตรวจสอบ` mark.
- Text generated by the science core or the API (method, source and limitation text inside
  evidence) stays English under a Thai heading that says so (decision D11).
- Do not put a language in the URL and do not read cookies: both would make pages dynamic.

## How the language is chosen

The server and the first client render always use Thai. After hydration the choice saved in
`localStorage` (`lunaris.lang`) applies and `<html lang>` follows it (`LanguageSync`). If storage
is blocked, the choice is kept in memory for the session.

## Fonts

`thai-font.css` self-hosts Noto Sans Thai (`@fontsource-variable/noto-sans-thai`). Geist stays
first in the stack; Thai glyphs fall back to Noto Sans Thai.

## Tests in another language

Vitest component tests render Thai by default. Call `setLanguage("en")` first (from
`@/lib/i18n/language-store`) to test English, and `resetLanguageForTests()` afterwards.
